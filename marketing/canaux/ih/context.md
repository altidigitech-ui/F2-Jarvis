## 1. RÔLE D'IH DANS L'ÉCOSYSTÈME

IH a un double rôle :
1. **Publication régulière** — 1 post/semaine, focus produit StoreMD, résultats terrain
2. **Canal de lancement ponctuel** — Show IH quand un produit est lancé (App Store approuvé, nouveau produit)

IH n'est PAS un canal d'acquisition directe. L'audience IH (founders solo, SaaS makers) n'est pas notre cible (merchants Shopify), mais ce sont des gens qui peuvent connaître des merchants ou être influenceurs dans la niche. C'est un canal de visibilité complémentaire.

Priorité IH dans le stack : BASSE. Le cold sur les autres plateformes est prioritaire. IH = publication schedulée au batch samedi, 0 effort en semaine.

## 3. PUBLICATION RÉGULIÈRE — 1 POST/SEMAINE MERCREDI

### Cadence

1 post le mercredi. Préparé au batch samedi. Publié (copier-coller) le mercredi en 2 min. Pas de rédaction en semaine.

### Contenu

Focus produit. Pas de build in public, pas de vulnérabilité, pas de "voici nos échecs". On parle du produit, de ce qu'il fait, des résultats qu'il apporte aux merchants.

| Type | Format | Quand |
|------|--------|-------|
| **Update produit** | Ce qui a été livré, les résultats, les chiffres réels | Hebdo (mercredi) |
| **Guide actionnable** | Step-by-step lié à un problème que StoreMD résout | Quand on a la matière |
| **Data drop** | Statistiques terrain observées sur les boutiques scannées | Quand les données sont intéressantes |

### Règles de publication

- Titre ~51 caractères (longueur optimale IH, cf. algo.md)
- Poster le mercredi. Éviter le mardi (76% des posts du mardi = bottom 50)
- Chaque post contient des chiffres réels (pas inventés, BIBLE §3)
- Le contenu est DANS le post. Pas de lien blog externe sans contenu substantiel.
- Lien vers StoreMD OK dans le post (IH ne pénalise pas les liens)
- Lien en fin de post, pas au début
- Jamais d'annonce pure sans contexte. "We just launched X" sans insight = ignoré.
- ANTI-IA appliqué sans exception
- Ton neutre produit. Le produit parle de lui-même.

## 4. LAUNCH POSTS — SHOW IH

Quand un produit est lancé ou qu'un milestone majeur est atteint, on publie un Show IH. C'est un post plus gros que la publication hebdo.

### Quand activer un Show IH

| Trigger | Action |
|---------|--------|
| StoreMD accepté Shopify App Store | Show IH (simultané ou +1 jour avec le launch PH) |
| ProfitPilot lancé | Show IH |
| Nouveau produit studio lancé | Show IH |

### Format Show IH

```
Titre: "I built [product] for [audience] — [unique angle]"
Exemple: "I built StoreMD to find what's silently killing Shopify stores"

Corps:
- Pourquoi j'ai construit ça
- Le problème que je résous (avec données)
- Ce que ça fait concrètement
- Ce que j'ai appris en construisant
- Lien UTM
- Question ouverte à la communauté
```

### Timing launch

Publier le même jour que le launch PH (ou +1 jour si PH déjà saturé). L'algo IH récompense l'engagement dans la première heure — répondre à chaque commentaire rapidement.

## 5. MILESTONES POSTS

Quand un milestone est atteint, on poste dans la section "Milestones" IH.

### Milestones qui justifient un post

| Milestone | Format |
|-----------|--------|
| Premier payeur | Post milestone |
| 10 payeurs | Post milestone |
| 100€ MRR | Post milestone |
| 1 000€ MRR | Post milestone |
| 10 000€ MRR | Post milestone |

### Format milestone post

```
Titre: "Hit [milestone] with [product]"

Corps:
- Le chiffre + ce que ça représente
- 2-3 leçons apprises
- Ce qu'on prévoit ensuite
- Lien UTM
```

**Cadence milestones** : 1 post tous les 2-4 semaines maximum si milestone réel atteint. Pas de fake milestones. Pas de "we're growing" sans chiffres. BIBLE §3.

On répond :

## 9. ANTI-PATTERNS

| Interdit | Pourquoi |
|----------|----------|
| Build in public ("week X update", chiffres studio, vulnérabilité) | On vend le produit, pas l'histoire du fondateur |
| Cadence continue agressive (1 post/jour) | L'audience IH se lasse |
| Fake milestones ("we're growing fast" sans chiffres) | Communauté détecte |
| Ne pas répondre aux commentaires | Première heure + long tail importants |
| Crosspost identique IH + PH | Adapter le message à chaque audience |
| Poster le même contenu que sur Twitter/LinkedIn | Adapter le format et le ton |
| Poster le mardi | 76% des posts du mardi = bottom 50 |
| Annonces pures sans contenu de valeur | Ignoré par la communauté |
| Cibler des devs/SaaS builders (ils ne sont pas nos clients) | BIBLE §5 |
| Em-dash, "Here's the thing", "At the end of the day" | Détecté IA. Cf. `ANTI-IA.md` |
| Inventer des chiffres / résultats | BIBLE §3 |
